# FoodDash

FoodDash is a Django backend for a food delivery platform. It provides domain models for customers, restaurant owners, couriers, restaurants, menus, and orders.

## Features

- Role-based users: customer, restaurant owner, and courier
- Restaurants with addresses, delivery settings, cuisines, and opening hours
- Categorized restaurant menus with available items and images
- Courier profiles with vehicle type, availability, and location
- Orders with delivery details, totals, and a validated status lifecycle
- Django admin for managing platform data
- Factory and Faker based database seed scripts

## Tech Stack

- Python 3.14
- Django 6.1
- PostgreSQL 16
- Redis 7
- Pillow
- django-environ
- uv
- Docker Compose

Redis is included in the local infrastructure as a dependency, but application caching or message queue integration is not configured yet.

## Local Setup

1. Start PostgreSQL and Redis:

   ```bash
   make up
   ```

2. Create a `.env` file in the project root:

   ```dotenv
   DEBUG=True
   SECRET_KEY=replace-with-a-long-random-secret
   DATABASE_URL=postgresql://postgres:postgres@localhost:5432/fooddash
   ```

   The Docker Compose database uses `postgres` as both the username and password.

3. Install dependencies:

   ```bash
   uv sync
   ```

4. Apply migrations:

   ```bash
   make migrate
   ```

5. Create an administrator account:

   ```bash
   make createsuperuser
   ```

6. Start the development server:

   ```bash
   make runserver
   ```

Open:

- Application: http://127.0.0.1:8000/
- Django admin: http://127.0.0.1:8000/admin/

## Database Seed Data

Seed scripts create realistic demo data in batches. Run them in this order:

```bash
uv run python seeds/seed_users.py --count 1000
uv run python seeds/seed_couriers.py
uv run python seeds/seed_restaurants.py --count 100
uv run python seeds/seed_orders.py --count 1000
```

Defaults are larger and suitable for load testing:

- Users: 100,000
- Restaurants: 5,000
- Orders: 500,000

The seed scripts require PostgreSQL and the relevant earlier seed data:

1. Users must exist before courier profiles and restaurants are created.
2. Restaurants and active menu items must exist before orders are created.
3. Customers and couriers must exist before orders are created.

User passwords generated by the seed scripts use `password123`.

## Order Lifecycle

An order can move through the following statuses:

```text
Placed -> Accepted -> Preparing -> Ready -> Picked up -> Delivered
```

From the `Placed` status, an order can also be rejected or cancelled. `Accepted` and `Preparing` orders can be cancelled. `Delivered`, `Cancelled`, and `Rejected` are terminal states.

## Development Notes

- Keep business logic out of views and serializers; place it in `utils.py` or `services.py`.
- Add drf-spectacular schemas to a separate `schemas.py` module when API endpoints are introduced.
- Prefer Django REST framework viewsets for reusable API resources.
- Environment variables are loaded from `.env`.
- Uploaded files are stored in `media/`.
